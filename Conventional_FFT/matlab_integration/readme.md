# MATLAB Integration with Verilog FFT CSV Output

This guide explains how to connect the **8-point Verilog FFT simulation** with **MATLAB** using the generated `fft_output.csv` file.

The workflow is:

```text
Verilog FFT Testbench
        |
        | Simulation
        v
fft_output.csv
        |
        | MATLAB readtable()
        v
MATLAB Analysis
        |
        +--> Frequency Domain
        +--> Magnitude Spectrum
        +--> Phase Spectrum
        +--> Verilog vs MATLAB FFT Comparison
```

---

## 1. Required Files

Keep the MATLAB script and CSV file in the **same folder**.

Recommended folder structure:

```text
FFT_MATLAB/
|
+-- fft_output.csv
|
+-- plot_fft.m
|
+-- README.md
```

### Files

| File | Purpose |
|---|---|
| `fft_output.csv` | FFT output generated by the Verilog testbench |
| `plot_fft.m` | MATLAB script that reads and analyzes the CSV |
| `README.md` | Instructions for using the MATLAB integration |

> **Important:** The MATLAB script expects the file to be named exactly `fft_output.csv` unless the filename is changed inside `plot_fft.m`.

---

# 2. Generate the CSV from Vivado

Run the **Behavioral Simulation** of the Basic FFT design using the final testbench.

The testbench contains code similar to:

```verilog
file = $fopen("fft_output.csv", "w");
```

When the FFT output becomes valid, the testbench writes:

```text
Bin,Real,Imaginary
```

followed by the eight FFT output bins.

The simulation console should show:

```text
*** FFT DATA SAVED TO fft_output.csv ***
```

---

# 3. Locate `fft_output.csv`

Vivado may create the CSV in the simulator's working directory rather than directly inside the Verilog `testbench` folder.

Search the Vivado project directory for:

```text
fft_output.csv
```

Open the file and verify that it contains data similar to:

```text
Bin,Real,Imaginary
0,...
1,...
2,...
3,...
4,...
5,...
6,...
7,...
```

Do not modify the CSV manually.

---

# 4. Create the MATLAB Folder

Create a separate folder for MATLAB analysis.

For example:

```text
FFT_MATLAB/
```

Copy these two files into it:

```text
fft_output.csv
plot_fft.m
```

The final structure should be:

```text
FFT_MATLAB/
|
+-- fft_output.csv
+-- plot_fft.m
```

---

# 5. Open the Folder in MATLAB

Open MATLAB.

In the **Current Folder** panel, navigate to:

```text
FFT_MATLAB
```

You can also use:

```matlab
cd('path_to_your_FFT_MATLAB_folder')
```

Verify that MATLAB can see the CSV:

```matlab
isfile('fft_output.csv')
```

The expected result is:

```text
ans =

  logical

   1
```

If the result is `0`, MATLAB is not currently looking at the folder containing the CSV.

---

# 6. Run the MATLAB Script

Run:

```matlab
plot_fft
```

MATLAB will execute:

```matlab
data = readtable('fft_output.csv');
```

and extract:

```matlab
k  = data.Bin;
Re = data.Real;
Im = data.Imaginary;
```

The complex FFT output is reconstructed using:

```matlab
X_hw = Re + 1i*Im;
```

---

# 7. Set the Sampling Frequency

The MATLAB script contains:

```matlab
Fs = 8000;
```

This means:

```text
Sampling Frequency = 8000 Hz = 8 kHz
```

Change this value if your system uses another sampling frequency.

For example:

```matlab
Fs = 10000;
```

for 10 kHz, or:

```matlab
Fs = 1000000;
```

for 1 MHz.

### Important

The sampling frequency is **not the amplitude of the samples**.

The input samples are signal amplitudes, while `Fs` determines the time spacing between samples and the frequency represented by each FFT bin.

---

# 8. Frequency Resolution

For an N-point FFT:

\[
\Delta f = \frac{F_s}{N}
\]

For the current 8-point FFT:

\[
\Delta f = \frac{8000}{8}=1000\text{ Hz}
\]

Therefore the FFT bins are:

| FFT Bin | Frequency |
|---:|---:|
| X[0] | 0 Hz |
| X[1] | 1 kHz |
| X[2] | 2 kHz |
| X[3] | 3 kHz |
| X[4] | 4 kHz |
| X[5] | 5 kHz |
| X[6] | 6 kHz |
| X[7] | 7 kHz |

The frequency axis is calculated in MATLAB using:

```matlab
Frequency = k * Fs / N;
```

---

# 9. Time Domain vs Frequency Domain

The values entered into the Verilog testbench are **sampled amplitudes in the time domain**.

For example:

```text
x[n] = [0.10, 0.20, -0.10, 0.15, -0.20, 0.05, 0.25, -0.15]
```

In the time domain:

```text
X-axis = Time / Sample Number
Y-axis = Amplitude
```

After the FFT:

```text
X-axis = Frequency
Y-axis = Magnitude
```

Therefore:

```text
TIME DOMAIN
    |
    | x[n]
    v
8-Point FFT
    |
    | X[k]
    v
FREQUENCY DOMAIN
```

---

# 10. Q1.15 Fixed-Point Format

The Basic FFT uses **Q1.15 fixed-point representation**.

The conversion is:

\[
\text{Decimal Value} =
\frac{\text{Signed Integer}}{32768}
\]

For example:

```text
0.10 × 32768 ≈ 3277
```

which is represented approximately as:

```text
0x0CCD
```

The MATLAB reference calculation should use the **exact quantized Q1.15 input values** used by the Verilog hardware.

This avoids introducing an unnecessary difference between the MATLAB and hardware inputs.

---

# 11. MATLAB Reference FFT

The MATLAB script reconstructs the exact Q1.15 input and calculates:

```matlab
X_matlab = fft(x, N);
```

This provides an independent software reference.

The comparison is:

```text
                  Same Q1.15 Input
                         |
             +-----------+-----------+
             |                       |
             v                       v
       Verilog FFT              MATLAB fft()
             |                       |
             v                       v
        X_hardware              X_matlab
             |                       |
             +-----------+-----------+
                         |
                         v
                    Error Analysis
```

---

# 12. Error Calculation

The complex FFT error is:

```matlab
Error = X_matlab - X_hw;
```

The magnitude of the error is:

```matlab
Absolute_Error = abs(Error);
```

The maximum error is:

```matlab
Maximum_Error = max(Absolute_Error);
```

The script also calculates:

```matlab
Mean_Error = mean(Absolute_Error);
```

and:

```matlab
RMS_Error = sqrt(mean(Absolute_Error.^2));
```

For the verified Basic FFT example, the maximum absolute error was approximately:

```text
8.57 × 10^-6
```

which is very small and consistent with fixed-point quantization/rounding.

# 13. MATLAB Plots

Running `plot_fft` generates several plots.

## Real Component

```text
X-axis = Frequency (Hz)
Y-axis = Real Part
```

## Imaginary Component

```text
X-axis = Frequency (Hz)
Y-axis = Imaginary Part
```

## Frequency-Domain Magnitude

```text
X-axis = Frequency (Hz)
Y-axis = |X[k]|
```

This is the main frequency-domain spectrum.

## Phase Spectrum

```text
X-axis = Frequency (Hz)
Y-axis = Phase (Radians)
```

## Hardware vs MATLAB

The MATLAB script compares:

```text
Verilog FFT
vs
MATLAB FFT
```

The two spectra should closely overlap if the hardware implementation is correct.

---

# 14. Single-Sided Spectrum

For a real-valued input signal, the FFT has conjugate symmetry.

Therefore, the conventional single-sided spectrum only displays:

\[
0 \leq f \leq \frac{F_s}{2}
\]

For:

```text
Fs = 8 kHz
```

the single-sided spectrum covers:

```text
0 Hz → 4 kHz
```

This is generally the most useful spectrum to present in a project report.

---

# 15. Changing the Input Samples

If a new set of 8 sampled amplitudes is provided, change the input samples in the Verilog testbench.

Example:

```verilog
sample[0] = 0.5;
sample[1] = -0.2;
sample[2] = 0.3;
sample[3] = 0.1;
sample[4] = -0.4;
sample[5] = 0.2;
sample[6] = 0.6;
sample[7] = -0.1;
```

Then:

1. Run the Verilog Behavioral Simulation again.
2. Generate a new `fft_output.csv`.
3. Replace the old CSV with the new CSV.
4. Run `plot_fft` again in MATLAB.
5. Check the hardware-vs-MATLAB error.

The FFT RTL does **not** need to be changed just because the input samples changed.

---

# 16. Changing the Sampling Frequency

If the input sampling frequency changes, change:

```matlab
Fs = 8000;
```

in `plot_fft.m`.

For example, for:

```text
Fs = 16 kHz
```

use:

```matlab
Fs = 16000;
```

The FFT hardware itself does not need to change just because `Fs` changes. `Fs` determines how the FFT bins are labelled in Hz.

---

# 17. Troubleshooting

## Error: `fft_output.csv was not found`

Check:

```matlab
pwd
```

Then:

```matlab
dir
```

Make sure `fft_output.csv` appears in the list.

You can also check:

```matlab
isfile('fft_output.csv')
```

---

## MATLAB shows incorrect frequency values

Check:

```matlab
Fs = 8000;
```

Make sure it matches the actual sampling frequency.

---

## Hardware and MATLAB FFT do not match

Check:

1. The CSV was generated by the latest Verilog simulation.
2. The input samples in MATLAB correspond to the exact Q1.15 values used by Verilog.
3. The FFT output order is correct.
4. The real and imaginary columns are not swapped.
5. The Q1.15 scaling is correct.
6. `N = 8` matches the hardware FFT size.

```text
                      |
                      v

                      v

    Hardware FFT             MATLAB FFT
          |                       |
          +-----------+-----------+
                      |
                      v
               Error Analysis
                      |
                      v
              Frequency Spectrum
```

For the final multiplier-optimized FFT, use the same process:

```text
Basic FFT
    |
    +--> CSV --> MATLAB --> Reference Result
    |
    +--> Area / Power / Timing
    |
    v
Baseline


Optimized FFT
    |
    +--> CSV --> MATLAB --> Verify Same Result
    |
    +--> Area / Power / Timing
    |
    v
Compare with Baseline
```

This allows the MATLAB verification environment to remain the same while changing only the FFT hardware architecture.
